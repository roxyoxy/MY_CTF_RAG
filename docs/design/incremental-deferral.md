# M2-③ 增量建库缓议书（真增量为什么不做）

> 状态：甲案配套文件，A 于 2026-09-29 拍板"diff 检测 + 墓碑继承 +
> 全量重建 + 缓议书"。本文是缓议书本体：真增量（只处理新增文档、
> 不碰旧账）被否决的完整论证，供 M5 复议时翻案或维持原判。
> 非契约；冲突时以各 .h 为准。

## 1. 考题回顾

M2-③ 的核心考题（TASKS 册上原文）：**id 稳定性——字典序下标遇
中间插入会连锁位移**。

推演（以 ctf-wiki 入库为实弹场景）：

```
data/ 现有：ai_security(4) crypto(4) misc(*) pwn(4) re(4) web(4)  ← 24 篇，id 0..23
ctf-wiki 带来 mobile/ 目录：字典序 ... misc < mobile < pwn ...
                                        ↑ 卡在中间
```

- `mobile/xxx.md` 插进位置 k → docs k..23 全体 doc id +1
- doc id 变 → chunk 归属变 → 这些文档的所有 chunk_id 重排
  （chunk id 全局连续打包，前面插了块后面全体前移）
- chunk_id 变 → postings 里所有受影响条目要改写 +
  chunk_lengths 要重新拼接

## 2. 核心论证：打包 id 与增量 merging 互斥

M1 选定的注册表模式（id = vector 下标，O(1) 直达访问）与
"免重排的增量合并"是一对**对偶代价**：享受了 id 稠密直达的
查询红利（search 的 scores 稠密向量化提案、chunk_lengths 下标
直寻的账本红线都吃这个格式），就要在语料变更时付出全量重编号
的重建成本。

量级账：改写受影响的 postings = O(账本总量)，**与全量重建同阶**；
但实现要同时做拼接 + 重编号 + 归并三件事，代码复杂度翻几倍。
在 n=24（目标 59）规模下，这是"用复杂度换零收益"。

结论：这不是实现水平问题，是 M1 选型的结构性代价。要真增量，
必须先推翻 id 打包——那就是乙案。

## 3. 三案死因档案

| 案 | 内容 | 死因 |
|---|---|---|
| 乙 | 稳定 id 重构（id 与位置解耦） | 稀疏 id 杀 chunk_lengths 下标直寻红线（TASKS §2）；M5 scores 稠密向量化提案（吃 id 稠密 0..N-1）陪葬；loader 契约 + persist 快照格式连环重写；Qt 外包件正按现行契约施工，全部作废。n=59 下收益为零 |
| 丙 | 追加式快路径（只支持尾部追加） | 被自家弹药击毙：ctf-wiki 含 mobile/ 新类目，字典序必卡中间，快路径永不触发。为永不触发的路径写代码是最贵的浪费 |
| 乙′ | id 留间隙（每 doc 预留槽位给中间插入） | doc id 留了间隙，chunk_id 仍打包——除非 chunk_lengths 改 map，撞红线，同乙 |

## 4. 甲案实际交付了什么（不是空头缓议）

1. **corpus_diff.h 第八契约**：diff_corpora 双指针归并 O(n+m)，
   产出 added/removed/edited 纯事实——未来任何增量方案的第一
   个零件都是它
2. **墓碑继承**：inherit_tombstones 按 path 把删除标记带过
   重建——M2-④ 签字的"编辑即复活"已知边界就此关闭
3. **main 启动分支**：CORPUS_CHANGED 时收获旧快照 → diff 报告
   → 继承 → 重建 → save，一条龙自动化
4. **本缓议书**：论证入册，翻案有据

## 5. 复议触发条件（何时重开本题）

满足任一条即值得重开：

- 语料规模 ×1000（10^4~10^5 文档量级），全量重建进入分钟级，
  用户可感知
- M5 对比实验实测重建耗时，数据证明 rebuild 是检索延迟或
  运维体验的瓶颈
- 出现高频变更场景（如在线增量投喂 writeup 的运营需求）

## 6. 复议时的方向指路

- **段式方案（Lucene 同款）**：索引切成多段，新语料建小段、
  查询跨段归并、后台异步合并。不动 id 契约，段内仍打包；代价
  是 search 要改多路归并（M5 的 RRF 混合检索天然是归并练手）
- **稳定 id 重构（乙案复活）**：id 改 path 哈希或持久自增，
  chunk_lengths/scores 改稀疏结构，persist 格式升版。代价清单
  见 §3；收益是彻底消灭重编号

判断框架不变：优化三规则第 3 条——先量级关，再动代码。

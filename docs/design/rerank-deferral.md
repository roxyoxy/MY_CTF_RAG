## 1. 议题回顾

AI-C 的问题：现代 RAG 管线图里，检索链通常是"召回（BM25 + 向量）
→ 融合（RRF）→ **重排（rerank / cross-encoder）** → 返回"，
本项目 M3 只做到融合，重排这一格是空的——是遗漏还是设计？

裁定：**有意省略**，论证如下。

## 2. 核心论证：145 chunks 规模下得不偿失

rerank 的标准形态 = cross-encoder 对 (query, passage) 逐对做一次
Transformer 前向推理，用相关性分替代融合分重排 top-k。

量级账（优化三规则第 3 条同款判断框架）：

- **收益侧**：rerank 改善的是"召回集合大、粗排噪声多"的场景
  （10^3~10^4 候选里淘金）。本项目全语料 145 chunks，BM25 +
  向量双路各取 top-k 后候选池本就只有几十条；且 Flat 向量路是
  exact 检索非 ANN 近似，召回集没有近似损失，粗排噪声天然有限。
- **成本侧**：本地 CPU 上 cross-encoder 每候选一次前向推理，
  几十条候选 = 秒级附加延迟，查询体验直接劣化；还需引入第二个
  模型（reranker 权重 + 推理通道），provider 抽象为它扩家。

结论：秒级延迟换边缘排序收益，量级关过不去。

## 3. 防线：不缺格的证明责任交给 M5

有意省略 ≠ 永久省略。M5 对比实验（BM25 / Dense-Flat /
Dense-HNSW / Hybrid 四路 recall / nDCG）自带排序质量数据：

- Hybrid 路 nDCG 明显低于各单路 recall 表现应有的水平 →
  粗排融合在丢分 → rerank 复议证据成立
- nDCG 达标 → 空格坐实为"当前规模下的正确设计"，本缓议书
  转为定案记录

## 4. 复议触发条件（满足任一即重开）

- M5 实测 hybrid nDCG@10 不达标，且差距指向排序而非召回
- 语料扩容一个量级以上（10^3 chunks 以上），候选池噪声变大
- 答辩演示需要"业界完整管线"叙事补全

## 5. 复议时的方向指路

- 通道：不自研推理（三条不自研红线同权适用）；候选 = M4 LLM
  后端（llama.cpp 生态）的 reranker 模型或独立推理通道，届时
  与 M4 后端选型一并裁
- 位置：钉在 RRF 之后、返回用户之前，只重排 top-k（k <= 50）
- 与 embedder 共享"成熟组件 + provider 边界"的既有模式，
  rerank 接口是 EmbedProvider 的兄弟，不是它的扩展

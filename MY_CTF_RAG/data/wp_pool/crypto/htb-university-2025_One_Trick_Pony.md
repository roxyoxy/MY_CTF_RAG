## Analyzing the source code

From a high level overview, we see the challenge provides a standard 3-choice menu from which we can do the following:

- Receive a signature of a message chosen by us.
- Predict a $408$-bit OTP generated by the TinselRNG. If the prediction is correct, we get the flag. We know the OTP length because the flag is $46$ bytes without the $5$-byte flag format. So $51$ bytes in total, which makes it $51 \cdot 8 = 408$ bits.
- Disconnect from the challenge.

Looking at how we get the flag, it looks like we have to find a way to crack TinselRNG and manage to predict following outputs which means that we should do it using the first option.

Notice that we are limited to using the first option 2000 times.

Looking at the source code of the signature generation method, we see that it is a classic DLP-based signature generation algorithm which can be algebraically represented as:

$S = H^x \pmod P$

where:

- $H$ -- the SHA-512 hash digest of the message $M$
- $x$ -- the private exponent used to sign the message. This is a $500$-bit value generated by the TinselRNG.
- $P$ -- the prime modulus used for all operations (i.e. exponentiation, addition)
- $S$ -- the signature of the message $M$

```python
assert isPrime(FROST_PRIME := 0x1a66804d885939d7acf3a4b413c9a24547b876e706913adec9684cc4a63ab0dfd2e0fd79f683de06ad17774815dfc8375370eb3d0fb5dce0019bd0632e7663a41)

def frostscribe_signature(msg):
    blizzard = hashlib.sha512(msg.encode()).digest()
    snowmark = int.from_bytes(blizzard, "big") % FROST_PRIME
    lantern_key = frostrng.gather_sparkles(500)
    etch = pow(snowmark, lantern_key, FROST_PRIME)
    return {"signature": str(etch)}
```

We are given the prime modulus so that would be a good starting point for our analysis. First, let us inspect TinselRNG.

```python
class TinselRNG:
    def __init__(self, bits):
        self.holly_prime = getPrime(bits)
        self.sleigh_seed = randint(1, self.holly_prime)

    def sparkle_bit(self):
        if self.sleigh_seed == 0:
            self.sleigh_seed += 1
        while True:
            shimmer = pow(self.sleigh_seed, (self.holly_prime-1)//2, self.holly_prime)
            yield int(shimmer == 1)
            self.sleigh_seed = (self.sleigh_seed + 1) % self.holly_prime
            if self.sleigh_seed == 0:
                self.sleigh_seed += 1

    def gather_sparkles(self, l):
        bits = ''
        for i, b in enumerate(self.sparkle_bit()):
            if i == l: break
            bits += str(b)
        return int(bits, 2)

frostrng = TinselRNG(34)

print(f'{frostrng.holly_prime = }')
```

An experienced eye should identify that this PRNG looks like a Legendre-based PRNG, in other words, a PRNG based on the Legendre Symbol.

```python
shimmer = pow(self.sleigh_seed, (self.holly_prime-1)//2, self.holly_prime)
yield int(shimmer == 1)
```

Let the PRNG's seed be $a$. The PRNG outputs $1$ if $a$ is a quadratic residue.

Equivalently, if the Legendre symbol of $a$ is $1$.

Equivalently, if the value $\begin{pmatrix} a \\ \hline p \end{pmatrix} = a^\frac{p-1}{2} \pmod p$ equals $1$.

In any other case, it outputs $0$.

# Solution

### Solving the DLP and recovering raw PRNG binary output

First of all, to crack the PRNG, we would need to interact with it and this is achievable by the first option. However, to obtain the PRNG output from the first option, we need to solve the DLP which is known to be a *hard* problem and for a $512$-bit modulus it is infeasible for a modern computer. However, assuming that the challenge is solvable, let us take a deeper look at the prime modulus.

```python
sage: P = 0x1a66804d885939d7acf3a4b413c9a24547b876e706913adec9684cc4a63ab0dfd2e0fd79f683de06ad17774815dfc8375370eb3d0fb5dce0019bd0632e7663a41
sage: factor(P-1)
2^6 * 3^35 * 5^21 * 7^6 * 137^11 * 191^2 * 331^3 * 3469^2 * 3613^11 * 3967^6 * 16561^3
```

Whoops. This is destructive for DLP. We know that if the order of the multiplicative group of $\mathbb{F}_p$ has small factors (or even powers of them), the DLP can be solved separately in the subgroups formed by each small factor and then combine these partial DLPs with CRT to get the final DLP solution for the entire group. This is known as the Pohlig-Hellman attack and is directly implemented inside SageMath's `log` and `discrete_log` functions. In fact, SageMath suggests us the following in the documentation[^1] for `discrete_log`:

> If `x` has a `log` method, it is likely to be vastly faster than using this function. E.g., if `x` is an integer modulo , use its `log` method instead!

In our case, the private exponent $x$ is an integer so it would be significantly faster to use `log`. Below we can see a demonstration of how fast the DLP can be solved with the challenge's prime modulus.

```python
sage: version()
'SageMath version 10.3, Release Date: 2024-03-19'
sage: F = GF(P)
sage: g = F.multiplicative_generator()
sage: x = F.random_element()
sage: A = pow(g, x, P)
sage: %time log(A, g) == x
CPU times: user 54.7 ms, sys: 983 µs, total: 55.7 ms

True
```

Therefore, let us write a SageMath method to solve for the private exponent and recover the raw binary sequence outputted from the PRNG.

```python
import hashlib, json, sys
from pwn import remote, process
from sage.all import log, GF

P = 0x1a66804d885939d7acf3a4b413c9a24547b876e706913adec9684cc4a63ab0dfd2e0fd79f683de06ad17774815dfc8375370eb3d0fb5dce0019bd0632e7663a41
F = GF(P)

def solve_dlp_and_get_bits(msg):
    io.sendlineafter(b'> ', b'1')
    m = str(msg)
    io.sendlineafter(b'message: ', m.encode())
    sig = int(json.loads(io.recvline())['signature'])
    h = hashlib.sha512(m.encode()).digest()
    m = int.from_bytes(h, "big") % P
    x = int(log(F(sig), F(m)))
    bin_x = bin(x)[2:].zfill(500)
    return list(map(int, bin_x))

if len(sys.argv) > 1:
    host, port = sys.argv[1].split(':')
    io = remote(host, port,)
else:
    io = process(['python3', '../challenge/server.py'])
```

### Cracking the TinselRNG

But now we need to do something with these outputs. We still do not have a clear plan of how we can attack this PRNG. The only thing that stands out is the size of the prime which is unusually small - just $34$ bits. It turns out that this is where the core vulnerability of TinselRNG lies.

There should be various exploitation paths but the "intended" is described here [^2].

The small size of the modulus $p$ enables us to apply a Meet-in-the-Middle attack to recover the seed and be able to predict the next outputs. Since $p$ is bounded by $2^{34}$, we would need $2^{34} + 31$ bits in total.

For every call to the first option, we get $500$ bits so we would need approximately $\approx \dfrac{2^{34}+31}{500} + 1 = 263$ calls to get a total of $263 \cdot 500 = 131500$ bits. Then we can just keep the first $2^{34}+31$ and discard the rest. This can be implemented as:

```python
SIZE = 34
OUTS = 2**(SIZE//2)
while OUTS % SIZE != SIZE - 1:
    OUTS += 1
BITS_PER_SIGN = 500

prng_outs = []
chall_rng_called = 0
while len(prng_outs) < OUTS:
    prng_outs += solve_dlp_and_get_bits(1337)	# sign any message
    chall_rng_called += 1
TOTAL_BITS_GENERATED = chall_rng_called*BITS_PER_SIGN
prng_outs = prng_outs[:OUTS]
```

Now, we group these bits into $34$-bit integers:

```python
dwords = {}
for i in range(0, len(prng_outs), SIZE):
    dword = int(''.join(str(i) for i in prng_outs[i:i+SIZE]), 2)
    dwords[dword] = i // SIZE
```

The `dwords` dictionary should look like:

$$\{N_0: 0, N_1: 1, N_2: 2,\ ...,\ N_{505290271}: 505290271\}$$

where $N_i$ the integer $b_{34i + 0}b_{34i+1}b_{34i+2} \dots b_{34i+33}$ and $b_0b_1b_2$ means concatenation of the bits $b_0, b_1, b_2$.

The size of the dictionary was determined by $\dfrac{2^{34}+31}{34} = 505290271$.

Then, we initialize the RNG with the seed $a = 1$.

```python
class RNG:
    def __init__(self, p):
        self.p = p
        self.a = 1
```

It is time to run our local RNG until we get a number already present in our large dictionary. We start with $a = 1$ and increment each time by multiples of $2^{34}$.

```python
STEP = 2**(SIZE//2)

while True:
    my_prng_out = rng.getrandbits(SIZE)
    if my_prng_out in dwords:
        seed = rng.a
        break
    rng.a += STEP
```

Now, suppose we find a match at the dictionary index $1000$, this means that we found the seed just before the $1000^{th}$ $34$-bit integer is generated and we are able to reproduce the following outputs $1001, 1002,\ ...,\  505290271$. In general, if the size of the dictionary is $S$ and a match was found at index $j$:

$[0, 1, 2,\ \dots,\ j\ ,\ S-j+1,\ S - j + 2,\ \dots\ ,\ S]$

then we can clone the PRNG from the $j^{th}$ integer and compute the $34$-bit outputs $S - j + 1, S - j + 2,\ \dots\ S$ .

Now we can update the seed but do not forget that our end goal is to predict the random OTP in option 2. The challenge RNG has already run $263$ times and the call for the OTP will be the $264^{th}$. Therefore, we need to sync with the challenge's RNG by generating and discarding the rest $34 \cdot (j + 1)$ bits.

```python
rng.a = seed
SEED_INDEX = dwords[my_prng_out]
SYNCED_BITS = (SEED_INDEX+1)*SIZE
BITS_TO_SYNC_LEFT = TOTAL_BITS_GENERATED - SYNCED_BITS
# sync with challenge RNG
# discard these bits
_ = rng.getrandbits(BITS_TO_SYNC_LEFT)
```

Finally, we can generate the OTP locally and send it to option 2 and get the flag.

```python
FLAG_LEN = 46 + 5
otp = bin(rng.getrandbits(FLAG_LEN*8))[2:]
io.sendlineafter(b'> ', b'2')
io.sendlineafter(b'(in bits): ', otp.encode())
print(json.loads(io.recvline())['starshard'])
```



## Getting the flag

A final summary of all that was said above:

1. Identify that the goal is to crack the Legendre PRNG to compute the OTP.
2. Notice that we need to solve the DLP to directly access the PRNG outputs.
3. Knowing enough PRNG outputs, we can perform a Meet-in-the-Middle attack and be able to clone the PRNG and predict the following outputs.
4. Having cloned the PRNG locally, we need to sync it to the challenge's remote PRNG and finally compute and send the random OTP to get the flag.

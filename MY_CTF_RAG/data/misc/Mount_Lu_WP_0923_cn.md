## Flag

```
npusec{A1w4Ys_5tAy_1n_H3rE}
```

（`A1w4Ys_5tAy_1n_H3rE` = "always stay in here"，与陷阱假 flag "never gonna give you up" 成对呼应。）

---

## 解题思路（30 秒版）

表面二维码 8 个方向扫码结果相同，解码出的诗句把「横」「侧」**故意互换**——全题主线就是"换视角"。RGBA 的 **alpha 通道只有 254/255 两个值**（1/255 对比度隐写），提取出 222×222 位图 = **6×6 块 37×37**。偶数块是 18 个真 QR 碎片，按列序拼出**假 flag**（`npulie{...}`，Rickroll）；奇数块是**反色汉信码 V8**——37×37 恰好同时是 QR V5 和汉信码 V8 的合法尺寸，这就是题目名的含义：站在 QR 这座"山"里，永远认不出另一座山。奇块每块 Text 模式编码 2 字符，沿用偶块泄露的列序拼接 → ROT13 → base64 → 真 flag。

## 主要分析过程

### 1. 表面层：一个"怎么扫都一样"的二维码

用 zbar 脚本对表面码做 4 旋转 × 镜像/转置共 8 个方向逐一扫码，结果全部相同：

```
这里似乎什么也没有呢，这段代码又是啥意思呢？4oCc5L6n4oCd55yL5oiQ5bKt4oCc5qiq4oCd5oiQ5bOw
```

尾部 base64 解码 = **「侧」看成岭「横」成峰**——原诗"横看成岭侧成峰"的横侧被出题人互换。

- 含义 1：整题的关键动作是**换视角**（怎么转图都没用，方向反了）；
- 含义 2：`challenge.zip` 与 `challenge.png` 字节完全相同，纯干扰项。

### 2. alpha 通道：1/255 对比度的第二层

逐通道看直方图：R/G/B 承载表面码，**A 通道只有 254 和 255 两个值**——肉眼完全不可见，但信息就藏在这 1/255 里。

提取规则：255→1、254→0；每个逻辑模块是 12×12 像素，取**中心 6×6** 采样抗边界干扰 → 得到 **222×222 隐藏位图**。

```
222 = 6 × 37  →  切成 6×6 = 36 块，每块 37×37
```

36 块呈棋盘布局：**偶数块 (r+c)%2==0** 纹理是标准 QR（18 块，各自可扫）；**奇数块**是均匀棋盘格底纹 + 每块约 175 处偏差——"另一种东西"。

![图2：alpha 隐写层全景](图片/2_alpha全景.png)

### 3. 偶数块：出题人送你的假 flag（思维锚）

18 个偶块各自扫出 2~3 个字符。行序拼接不成文，**按列序**拼得 42 字符：

```
oaO1oTyyr04mqwAlKmxjoz40K0pkqxIsrGO1K3IjsD
```

ROT13 → base64：

```
npulie{N3v3r_90nn4_G1vE_y0u_up}
```

`npulie` ≠ `npusec`——**假 flag**，提交即被 Rickroll。事后看这层的真实作用有两个：

1. **锚定**：把"这是 QR + 列序 + ROT13 + b64"的思维定式焊死在选手脑子里；
2. **泄题**：它悄悄告诉你最终层的拼接规则（列序）和编码管线（ROT13+b64）——陷阱本身就是提示。

### 4. 奇数块：QR 框架下的三重反证（卡点记录）

奇块按 **QR Version 5**（17+4×5=37）处理，穷举到底：

- **RS 全败**：8 种掩码 × 2 种极性 × 4 种纠错等级，全部纠错译码失败；
- **格式信息非法**：QR 的 15-bit 格式信息不匹配任何合法 BCH 纠错码——连"这是个 QR"的身份位都通不过；
- **纠错结构不存在**：18 块 raster 互相比较，差异模块仅 156/1369 且高度重叠——QR 式纠错码字应有的"块间独立随机性"根本不存在。

三条独立证据同时指向同一个结论：**它根本不是 QR**。但当时的我在 QR 框架里越陷越深，转而构造"自定义位域编码"模型去解释那 175 处偏差——模型越来越圆，flag 越来越远。（这一步的教训见文末反思。）

### 5. 破局：四角定位图案 → 汉信码

放下"待解的 QR"，把奇块取反的渲染图当成**一张码的标本**重新看——码制识别的第一特征从来不在数据区，而在**功能区：定位图案的数量、形状、位置**。这一看就看出问题：**四个角各有一个 7×7 定位图案**，而 QR 永远只有三个角。四角定位 + 四角图案不对称（用于判定方向），正是国产**汉信码（Han Xin Code）**的标志特征——中国国家标准 GB/T 21049 / ISO/IEC 20830。

再用版本尺寸公式核对这层"尺寸碰撞"：

```
QR      : 17 + 4×5  = 37   ← 偶块走的路
汉信码  : 21 + 2×8  = 37   ← 同一尺寸，另一种合法身份！
```

37×37 在两种码制里都是合法版本——这解释了为什么之前一切"QR 参数穷举"注定失败：不是参数不对，是**身份错了**。

把奇块**逐位取反**后与汉信码 V8 的"固定/结构信息区"模板比对——**18 块全部零失配**：

| 参数 | 值 |
|---|---:|
| 版本 | 8（37×37） |
| 纠错等级 | 1 |
| 掩码 | 1 |
| 极性 | 反色（取反后为标准极性） |
| 码字 | 117 = 99 数据 + 18 RS |
| RS 域 | GF(256)，生成多项式 0x163 |

![图3：奇块取反后与汉信码 V8 模板对照](图片/3_汉信码对照.png)

顺带解开此前的假象：奇块底纹是棋盘格，我曾用"棋盘 XOR"提取翻转位并以为发现了自定义数据位域。真相是——汉信码 mask 1 在 (r+c) 为**偶**处翻转，而棋盘基线恰在 (r+c) 为**奇**处为 1，两者互补：

```
raw ⊕ checker_odd = (canonical ⊕ 1) ⊕ checker_odd = canonical ⊕ mask1
```

也就是说我手里那套"翻转模板"**本来就是解过掩码的汉信码数据矩阵**，只差没换码制识别、没走汉信码自己的码字重排。

### 6. 解码：每块 2 字符 × 18 块

每块的完整解码管线：

1. 取反 → 解 mask 1 → 按汉信码**行优先**读取数据区模块 → 936 bit = 117 码字；
2. **逆 13 路 picket-fence 重排**（汉信码特有的码字交错方式）→ 前 99 字节数据 + 18 字节 RS 校验——18 块**全部通过 RS(117,99) 校验**，零差错；
3. 数据流为汉信码 **Text 模式**：模式头 `0010` + 6bit 字符 + 6bit 字符 + 终止符 `111111`——每块恰好编码 **2 个字符**（2×6bit = 12 信息位）。

| (0,3) | 81 | (2,3) | qR | (4,3) | S5 |

## 工具与关键代码

**环境**：Python 3 + numpy + Pillow；扫码：zbar（脚本批量生成 4 旋转 × 镜像/转置 8 个方向逐一识别，输出存档 `_work/不识庐山/scan_results.txt`）；汉信码参考资料：GB/T 21049、ISO/IEC 20830、zint 开源实现（`hanxin.c`）。

**① alpha 提取（12×12 模块取中心 6×6，规避模块边界）**

```python
rgba = np.asarray(Image.open("challenge.png").convert("RGBA"))
alpha = rgba[..., 3]          # 只有 254/255 两个值
modules = (
    alpha[: 222 * 12, : 222 * 12]
    .reshape(222, 12, 222, 12)[:, 3:9, :, 3:9]   # 中心 6x6
    .mean(axis=(1, 3)) > 254.5                    # 255→1, 254→0
).astype(np.uint8)
# 222 = 6*37 → 6x6 块，每块 37x37
blocks = [modules[r*37:(r+1)*37, c*37:(c+1)*37]
          for r in range(6) for c in range(6) if (r + c) % 2]   # 18 个奇块
```

**② 码制校验哲学：不是"看着像"，是"固定区零失配 + RS 全过"**

判定奇块为汉信码 V8 不是靠肉眼，而是双重硬校验：取反后与 V8/ECC1/mask1 的固定+结构信息区模板**逐格比对零失配**，且每块 117 码字**全部通过 RS(117,99) 校验**（18/18）。两个独立强校验都过，码制识别才坐实。

**③ 完整 solver**（题目目录 `不识庐山_hanxin_solver.py`，一次性完成提取→识别→解码→拼序→出 flag）：

```
> py 不识庐山_hanxin_solver.py challenge.png --montage 副产物_18个汉信码解码标注.png

    (0, 1): Iw    (0, 3): 81    (0, 5): tm
    (1, 0): oa    (1, 2): qm    (1, 4): Km

```

**④ 数学佐证：为什么曾以为的"156 bit 私有数据"是幻觉**

卡点期间我曾把 18 块 raster 的差异模块当作 156 bit 独立私有数据并发现种种"结构体位域"假象。汉信码模型下的定量验证：

```python
flat = symbols.reshape(18, -1)
variable = flat.std(axis=0) > 0                       # 变化模块 support
rank = gf2_rank(flat[:, variable] ^ flat[0, variable]) # 中心化后的 GF(2) 秩
# 实测: support = 156, rank = 12
```

每块明文只有 12 bit（2 字符 × 6bit），经 RS 线性编码 + 交错重排 + 模块放置扩散后，恰好表现为"156 个变化模块、但线性空间只有 12 维"——**12 维线性扩散**，而非独立密文。所谓 byte19 恒落 'H'~'O'、9 个"随机字节"等假象，全是 raster 字节切割线性子空间产生的巧合。假设换成汉信码后，之前所有解释不通的观测一次性全部自洽。

## 最终获得 Flag

```
npusec{A1w4Ys_5tAy_1n_H3rE}
```

- 18 块 RS 校验 18/18 通过、7 bit symbol-padding 全零、固定区零失配——解码零歧义；
- 列序串经 ROT13 + base64 得到合法 flag，平台提交通过；
- 语义与陷阱层成对：假 flag "never gonna give you up" ↔ 真 flag "always stay in here"。

## 卡点与反思（本题最大的收获）

1. **锚定效应是本题真正的考点**：偶块全是真 QR，把码制假设焊死；之后每条反证（BCH 非法、RS 全败、纠错结构缺失）都被我用"更复杂的自定义编码模型"吸收掉，而不是触发"换假设"警报。正确姿势：**连续 2~3 轮同框架失败 = 强制开"换假设"分支，禁止在旧模型上继续投资**。
2. **反证的正确读法**：三条独立证据（身份位/纠错/统计结构）同时失败时，结论不是"参数没扫到"，而是"框架本身错了"。穷举 6 轮参数不如枚举 5 分钟"这个尺寸还能是哪些标准码"。
3. **把图当"码的标本"看，而不是当"待解的数据"看**：卡死后最有效的动作不是继续扫参数，而是回到图本身看码制一级特征——定位图案的数量/形状。四个角一直就摊在渲染图上，只是被"QR 数据区"的预设挡住了眼睛。
4. **重新描述问题时不能带预设**：带着自定义编码的预设去问"这些翻转像不像字形"，等于把问题本身问歪了；中立的问题是"这个块的定位图案和 QR 一样吗"——一个好问题比多一轮穷举值钱。
5. **尺寸碰撞值得主动检查**：任何"标准件"解码全败时，先查这个参数（尺寸/结构）在多少种标准里合法——37×37 = QR V5 = 汉信码 V8，出题人就赌你不知道后者。
